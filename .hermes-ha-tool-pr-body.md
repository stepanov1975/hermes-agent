## Summary
- replace the remaining per-call `asyncio.run()` path in `tools/homeassistant_tool.py`
- reuse persistent event loops for main-thread, worker-thread, and already-running-loop call modes
- add regression coverage for loop reuse and liveness when `_run_async()` is called from inside a running event loop

## Problem
`homeassistant_tool._run_async()` had been updated to reuse persistent loops for some sync call paths, but the branch used when already inside a running event loop still spawned a disposable thread and called `asyncio.run(coro)` per invocation.

That meant the tool could still create and immediately close a fresh loop for async-context calls, leaving `aiohttp` cleanup tied to dead loops and risking `Unclosed client session` / `Unclosed connector` warnings.

## Fix
- add a dedicated persistent background loop thread for the async-context branch
- submit coroutines with `asyncio.run_coroutine_threadsafe(...)`
- keep the existing persistent main-thread and per-worker-thread loop behavior

## Notes
This keeps the Home Assistant tool aligned with the persistent-loop bridge pattern already used elsewhere in Hermes, while closing the remaining async-context gap in this module.
